# 대화형 일기장 웹앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 질문에 답하면 Claude가 이어 묻고 일기 초안을 써 주는, 구글 로그인 기반 다중 사용자 일기 웹앱을 2026-12-01 발표 전에 Vercel에 배포한다.

**Architecture:** Next.js(App Router) 한 프로젝트에 화면과 서버 API를 둔다. 데이터는 Supabase Postgres에 두고 모든 사용자 테이블을 RLS로 막는다. 사용량 상한은 SECURITY DEFINER 함수 하나로 원자적으로 센다. Claude 호출은 서버 Route Handler에서만 하며, 규칙(질문 횟수·날짜·상한)은 순수 함수로 분리해 단위 테스트한다.

**Tech Stack:** TypeScript, Next.js 15, pnpm, `@supabase/ssr` + `@supabase/supabase-js`, Supabase CLI(마이그레이션·pgTAP), `@anthropic-ai/sdk`, Vitest, Playwright, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-17-diary-app-design.md`

## Global Constraints

- 수준: MVP/데모용. 스펙에 없는 기능·추상화를 더하지 않는다.
- 첫 질문 문구 고정: `오늘 하루는 어떠셨나요?`
- 후속 질문: 최소 3번, 최대 6번 (R2). [이제 일기 쓰기]는 후속 질문 3번 이후 활성 (R4).
- 사용자당 하루 1편, 하루 = 사용자 브라우저 로컬 날짜, 서버는 서버 시각 ±14시간 범위 날짜만 허용.
- 사용량 상한: 사용자당 하루 `QUOTA_PER_USER`(기본 20) 호출, 서비스 전체 하루 `QUOTA_GLOBAL`(기본 500) 호출. 질문 호출은 초안 1회분을 남기고만 허용. 상한의 "하루"는 서버 UTC 날짜.
- 모델은 환경변수 `ANTHROPIC_MODEL`로만 지정. 코드에 모델 ID를 하드코딩하지 않는다.
- 비밀값(`ANTHROPIC_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`)은 서버 전용 환경변수. `NEXT_PUBLIC_` 접두사 금지. 저장소 커밋 금지.
- 운영 로그인은 구글만. 로컬 Supabase에서만 이메일/비밀번호를 켜서 E2E에 쓴다.
- 테마 ≥ 8, 폰트 ≥ 10, 독립 선택, 테마·폰트는 코드 안의 데이터 목록(한 줄 추가로 확장).
- 사용자 답변 길이 상한 2000자.
- 테스트는 구현보다 먼저 커밋한다. 커밋된 테스트는 수정 금지(훅으로 차단).
- 작업 흐름: 태스크 하나 = GitHub 이슈 하나 = 워크트리 하나 = `beta` 대상 PR 하나. `main`에는 `beta` 단위로만 올린다.

## Review Focus

1. **한글 입력기(IME) 조합 중 Enter**: 조합 중인 Enter는 전송하지 않아야 한다(마지막 글자 잘림·이중 전송). → Task 6에 테스트.
2. **전송 버튼 연타·응답 대기 중 재전송**: 메시지가 두 번 저장되거나 상한이 두 번 깎이면 안 된다. → Task 6에 테스트.
3. **빈 답변·공백만 있는 답변, 2000자 초과 답변**: 전송 불가 또는 서버 400. → Task 2(검증 함수)와 Task 6에 테스트.
4. **대화 도중 자정이 지남**: 대화 중인 일기는 시작한 날짜에 그대로 속해야 한다(새 날짜로 새 일기 생성 금지). → Task 6에 테스트.
5. **스트리밍 도중 연결 끊김**: 사용자 답은 이미 저장되어 있고, 같은 상태에서 다시 시도할 수 있어야 한다(R14). → Task 6에 테스트.
